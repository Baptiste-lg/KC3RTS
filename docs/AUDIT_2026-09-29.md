# Code and CI audit — 2026-09-29

Scope: KC3 worker boundary, Elixir match process and simulation, browser
connection and local simulation, tests, build, live browser smoke and Pages
smoke. This is an audit of the current prototype; the product roadmap remains
in [PLAN.md](../PLAN.md).

## Corrected in focused commits

- Concurrent joins now resolve to the same supervised match process. A
  20-caller test checks the registry and shared PID.
- Reconnecting the browser ignores late replies and events from the previous
  channel, reports offline after disconnect and registers socket listeners
  only once. A lifecycle test exercises the old and new channels.
- Browser collision checks use nearby grid cells instead of scanning every
  villager for each moving villager. The 100-unit shared-goal test still checks
  spacing throughout movement; see [performance measurements](PERFORMANCE.md).
- Browser ticks copy resource and building objects only when they change. A
  test checks that earlier snapshots survive gathering, construction and
  combat. Nearest-center selection now uses one pass without sorting.
- World distance checks use direct squared components. This removes two
  general-purpose power calls from each distance calculation; the full server
  benchmark did not establish a separate end-to-end improvement.
- KC3 requests are JSON-encoded once. Unencodable data and invalid UTF-8 are
  rejected without crashing the adapter.

## Local verification

All checks passed on the audited tree: `mix format --check-formatted`,
`mix credo --strict`, `mix test`, `mix test --cover` with the pinned KC3 binary,
`npm run lint`, `npm run typecheck`, `npm run test:coverage`, `npm run build`,
`npm run smoke` and `npm run smoke:pages`. The KC3 suite passed 30 tests with
92.53% cover points. The browser suite passed 43 tests with 95.77% statement
coverage. Both smoke checks exercised WebGL, recruitment, wood delivery and
stop orders. The Pages build passed at its deployed `/KC3RTS/` base path.

## Remaining release risks

- The playable Phoenix and Pages simulations still run outside the KC3 worker.
  The worker currently proves one match's economy, construction, ticks and
  revision protocol; it does not own the playable rule set yet.
- `game:lobby` is shared and unauthenticated. Match count and lifetime are
  unbounded. It must remain a development endpoint until ownership, caps and
  expiry are implemented and tested.
- The server sends full snapshots at 10 Hz and its tick timer can drift under
  load. No versioned command acknowledgement or recovery contract exists.
- Unit collision is covered; static obstacle pathfinding and crowded
  chokepoint behavior remain unfinished. The enemy cannot fight or win.
- The browser build still warns about a JavaScript chunk above 500 KB. Bundle
  size is not a runtime frame-time measurement; profiling should guide a
  split or rendering change.

CI can only be confirmed on GitHub after the push. Local tests exercise the
same commands and KC3 library path as the five workflow jobs.
